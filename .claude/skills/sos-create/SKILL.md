---
name: sos-create
description: Turn an idea, a need, a calendar slot or a video into ready drafts for one Social OS account, humanized and rule-checked, and put them in the dashboard for approval.
---
**Skills rule:** at each step load the skills named here (and in the platform README) before doing the work. If another installed skill fits a step better, use it too and add it to `SKILLS.md`.
**Learning rule:** read `LESSONS.md` before starting (skip if already read this session). Any correction from the user, failed step, wasted spend or workaround found -> run `sos-learn` in that same turn (lesson + fix this skill + commit).

0. Before writing anything: ArtifactData `set posts/<id>` with status `draft`, the `format`, `accountId`, `platform`, a one-line `caption` (the working title) and `mediaUrls` []. The dashboard shows it as a blurred, shimmering card in that format while you build. Step 6 later overwrites it.
1. Read `platforms/<platform>/README.md` and load the writing skill it names (Instagram: ig-reel / ig-caption / ig-carousel / ig-story; LinkedIn: linkedin-post-writer; X: x-post / x-thread + twitter-algorithm-optimizer; YouTube: yt-script + yt-package + yt-seo + yt-chapters; Shorts: yt-shorts; Facebook: ig-caption / ig-repurpose + copywriting; Threads: x-post). One long piece into many: ig-repurpose / linkedin-repurposer / x-repurpose. Weak idea or hook -> `copywriting`. Use the account's `voice.md` and `style.md` wherever a skill asks for `~/.claude/<platform>/voice.md`.
2. Write the draft. Never invent numbers, clients or results; leave `{{your number}}` and say so. **Realism rule (user, 31 Oct):** the title promises exactly what the slides show (a "code"/"command" = one short line); every tip is something we tested, shown with a real example (real screenshot or real output we produced). Can't show it working -> drop the idea.
3. Run the platform humanizer (ig-human / linkedin-humanizer / x-human; Facebook/Threads also `content-humanizer`) and apply its fixes.
4. Media: carousels first look at real top carousels in `C:\Gaznil\social-os-media\carousel-library\` (competitors/ + from-gaznil/) and copy their layout ideas, not their content; then design as HTML with `frontend-design` + the account's `style.md` (`canvas-design` / `banner-design` for single graphics), images rendered to PNG (1080x1350 for Instagram feed, 1080x1920 for stories) into `C:\Gaznil\social-os-media\<account-id>\`. Never put media in git. Video = `prompt-guy` ONLY (user rule 31 Oct): it writes the paste-ready prompt and stops; Social OS never runs Edit King or Motion King. The prompt goes on the draft for the user to use. Post asks people to comment a keyword -> note it so Porotta gets the matching DM automation.
5. Write the post JSON to the scratchpad and run `python -m tools.sos.cli check <file>`; put the result in `problems`. Fix and re-check until empty, or leave the problems for the user to see.
6. ArtifactData `set posts/<id>` with status `waiting`, `plannedAt` = next free posting window for that account (settings/main), all docs/DATA.md fields present.
7. Tell the user one line: what is waiting and where to approve it.
8. Run `sos-learn` if the user changed or rejected the draft (what they changed = the lesson; voice/style lessons also go into the account's `voice.md` / `style.md`).
